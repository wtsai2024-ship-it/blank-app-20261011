ピタッと環境整備マスター（スマホアプリ版）
新人看護職員向けの環境整備学習ゲーム「ピタッと環境整備マスター」を、Streamlit Community Cloud で公開するスマートフォン向けアプリにしたものです。
ゲームを遊び、結果を記録し、みんなのランキングを見るところまで、すべてアプリの中で完結します（Googleフォームは使いません）。
対象：新人看護職員（研修・自己学習）
操作：スマホ縦向き・横向き・PC のどれでも可。スマホは「物品をタップ → 置き場所をタップ」が基本（ドラッグも可）
記録の保存先：Googleスプレッドシート（サービスアカウントで書き込み。スタッフはシートに触れません）
公開範囲：URLを知っている人のみ（URLは院内でのみ配布）
---
1. 何ができるか
画面	内容
シナリオ選択	5シナリオ（脳卒中回復期／開腹術後1日目／認知症・夜間せん妄／小児・付き添い入院／接触感染予防策・個室隔離）
① 病室を整える	物品11点を正しい定位置へ。正解するたびに、くまさんナースが根拠を表示する
② 五感を整える	音・光・気温・においの4問
③ ふりかえり	ランク・スコア・学び15件。ここで実施記録を登録する
🏅 ランキング	総合（一人ひとりのベスト）／シナリオ別／みんながつまずいた物品
管理者ページ	URLの末尾に `/admin`。パスワードで保護。全記録の一覧・絞り込み・CSVダウンロード・部署別の実施状況
記録する項目
スタッフが入力するのは次の2つだけです。氏名とメールアドレスは扱いません。
職番の下4桁 または ニックネーム（12文字以内。手入力）
部署（プルダウンから選択）
ゲーム側から自動で付く項目：日時・シナリオ・得点・ランク・片付け数・五感の正答数・ミス回数・ヒント回数・所要時間・誤配置した物品
スプレッドシートの「アプリ記録」タブに、次の列で1行ずつ追記されます。
```
日時 | 記録ID | 名前 | 部署 | シナリオ | 得点 | ランク | 片付け | 五感 | ミス | ヒント | 所要秒 | 間違えた物品
```
「1人」は 名前＋部署の組み合わせ で数えます（同じニックネームでも部署が違えば別の人）。
記録IDは1回のプレイごとの識別子です。通信の再送などで同じ記録が二重に登録されるのを防ぎます。

2. フォルダ構成
```
pitatto-app/
├─ streamlit_app.py            ← 入口。Community Cloud の「Main file」に指定する
├─ views/
│   ├─ game.py                 ← スタッフ用ページ（ゲームを全画面表示・記録の保存）
│   └─ admin.py                ← 管理者ページ（/admin）
├─ pitatto/
│   ├─ config.py               ← 部署の選択肢・シナリオ名・列見出し（変更はここ）
│   ├─ storage.py              ← スプレッドシートへの書き込み・読み込み・入力値の検証
│   ├─ ranking.py              ← ランキングの集計
│   └─ component.py            ← ゲームHTMLを Streamlit コンポーネントとして登録
├─ component/
│   └─ index.html              ← ゲーム本体（build_app.py で生成。直接編集しない）
├─ src/
│   ├─ game_app.src.html       ← ゲームの編集用ソース（文言・シナリオはここを直す）
│   └─ assets/                 ← くまさん・患者さんの画像（WebP 7点）
├─ build_app.py                ← src → component/index.html を生成する
├─ requirements.txt
├─ .streamlit/
│   ├─ config.toml             ← テーマ色など
│   └─ secrets.toml.example    ← secrets の見本（本物は GitHub に上げない）
└─ .gitignore
```
しくみ（ざっくり）
```
スマホのブラウザ
  └─ Streamlit アプリ（Community Cloud）
       ├─ ゲーム（component/index.html を iframe で全画面表示）
       │     │ 「記録する」  ──▶  Python（views/game.py）
       │     │                     ├─ 入力値を検証（storage.build_row）
       │     │                     └─ スプレッドシートに1行追記
       │     ◀── 保存結果・最新のランキング
       └─ 管理者ページ（/admin）── スプレッドシートを読んで一覧・CSV
```
ゲームと Python は Streamlit のコンポーネント通信（postMessage）でやりとりします。外部ライブラリやnpmのビルドは不要です。
Community Cloud のサーバーは再起動のたびにファイルが消えるため、記録は必ずスプレッドシートに置きます。
secrets が未設定のときは試運転モードになり、記録はサーバー内の `data/records.csv` に書かれます（再起動で消えます）。

3. 公開までの手順
所要時間の目安は、初めてで1〜2時間です。次の4段階で進めます。
手順A. 記録用スプレッドシートを用意する
Googleドライブで新しいスプレッドシートを作ります（例：「環境整備ゲーム アプリ記録」）。既存の記録用スプレッドシートを使っても構いません。その場合、「アプリ記録」という新しいタブに書き込むので、既存のシートには影響しません。
URLの `https://docs.google.com/spreadsheets/d/【ここ】/edit` の 【ここ】 を控えます（＝スプレッドシートのキー）。
共有設定は管理者のみのままにします（スタッフには共有しません）。
手順B. 書き込み用のサービスアカウントを作る（Google Cloud）
https://console.cloud.google.com/ を開き、新しいプロジェクトを作ります（例：`pitatto`）。
「APIとサービス」→「ライブラリ」で、次の2つを有効にします。
Google Sheets API
Google Drive API
「APIとサービス」→「認証情報」→「認証情報を作成」→「サービスアカウント」。名前は `pitatto-writer` など。ロールは付けなくて構いません。
作ったサービスアカウントを開き、「鍵」→「鍵を追加」→「新しい鍵を作成」→ JSON → ダウンロード。
このJSONファイルは合鍵です。メール添付や共有フォルダに置かず、作業後は安全な場所に保管してください。
JSONの中にある `client_email`（`…@….iam.gserviceaccount.com`）を、手順Aのスプレッドシートの「共有」に 編集者 として追加します（通知メールはオフで可）。
> 院内のGoogleアカウントが組織管理されている場合、外部ドメイン（サービスアカウント）への共有が禁止されていることがあります。共有できないときは、情報システム担当に確認してください。
手順C. GitHub に置く（非公開リポジトリ）
GitHub でPrivateのリポジトリを作ります（例：`pitatto-app`）。
くまさんの画像は院内利用を前提とした素材のため、必ず Private にします。
このフォルダの中身をアップロードします。
`.streamlit/secrets.toml` とサービスアカウントのJSONは上げません（`.gitignore` で除外済み）。
`component/index.html` は生成物ですが、Community Cloud では生成しないので一緒に上げます。
手順D. Streamlit Community Cloud で公開する
https://share.streamlit.io/ に GitHub アカウントでログインします（初回は Private リポジトリへのアクセス許可を求められます）。
「Create app」→「Deploy a public app from GitHub」。
Repository：手順Cのリポジトリ
Branch：`main`
Main file path：`streamlit_app.py`
App URL：覚えやすい名前（例：`hokuso-pitatto`）。このURLがスタッフに配るURLです。
「Advanced settings」→ Secrets に、`.streamlit/secrets.toml.example` を見本にして本物の値を貼ります。
`[admin] password`：管理者ページのパスワード
`[sheet] key`：手順Aで控えたキー
`[gcp_service_account]`：手順BのJSONの中身を1項目ずつ写す（`private_key` の `\n` はそのまま）
「Deploy」。数分で起動します。
公開範囲を「URLを知っている人」にする。 Private リポジトリから作ったアプリは、最初は非公開（自分だけ見られる）です。
アプリ右上の「Share」または「App settings」→「Sharing」で public に切り替えます。
リポジトリ（ソースコード・画像ファイル）は Private のままで、アプリの画面だけが公開されます。
公開設定のアプリはURLを知っていれば誰でも開けます。URLは院内の掲示・メールでのみ配布してください。
動作確認
スマホでURLを開き、1シナリオを最後まで遊んで「記録する」→ スプレッドシートの「アプリ記録」タブに1行増えることを確認
URL末尾に `/admin` を付けて開き、パスワードでログインできることを確認
管理者ページに「試運転モード」の黄色い警告が出ていないことを確認（出ていれば secrets の設定漏れ）
スタッフへの案内（例）
> 環境整備の学習ゲーム「ピタッと環境整備マスター」を公開しました。スマホで下のURL（またはQRコード）を開くと遊べます。
> 最後の「ふりかえり」画面で、**職番の下4桁かニックネーム**と**部署**を入れて「記録する」を押すと、実施記録が残ります。**氏名は入れないでください。**
> 右上の 🏅 から、みんなのランキングを見られます。
> ホーム画面に追加しておくと、アプリのように開けます（iPhone：共有ボタン →「ホーム画面に追加」／Android：メニュー →「ホーム画面に追加」）。

4. 運用
やりたいこと	方法
記録を見る・Excelで集計する	管理者ページ（`/admin`）→「CSVでダウンロード」（Excelでそのまま開けるUTF-8 BOM付き）
テストの記録を消す	スプレッドシートの「アプリ記録」タブで該当行を削除（ランキングには最大30秒で反映）
部署の選択肢を変える	`pitatto/config.py` の `DEPTS` を直して GitHub に反映（Community Cloud が自動で再起動）
管理者パスワードを変える	Community Cloud の「App settings」→「Secrets」
アプリを止める	Community Cloud の管理画面でアプリを削除（記録はスプレッドシートに残る）
知っておくこと
しばらく使われないとアプリが休止します。 休止中にURLを開くと起動ボタンの画面が出るので、押して1分ほど待ちます。研修の前には一度開いて起こしておくと安心です。
ランキングは30秒ごとに読み直します。ランキング画面の「↻ 最新」で、すぐに読み直せます。
誰でも記録を送れるURLなので、サーバー側で値を検証しています（部署は選択肢のみ、得点は0〜2220、シナリオ名は5種のみ、名前は12文字以内で記号 `< > " ' \` =` は不可）。
以前の Googleフォーム／GAS 版の記録（氏名・メールアドレス入り）とは別のタブに記録します。旧データは混ざりません。

5. ゲームを修正するとき
`src/game_app.src.html` を編集します（シナリオ・物品・根拠の文言は `const SCEN = [...]`）。
`python build_app.py` を実行し、`component/index.html` を作り直します。
シナリオ名を変えた・増やした場合は、`pitatto/config.py` の `SCENARIOS` も同じ名前にします（一致しない記録はサーバー側で受け付けません）。
GitHub に反映すると、Community Cloud が自動で再起動します。
手元のPCで試す
```bash
pip install -r requirements.txt
python build_app.py
streamlit run streamlit_app.py
```
secrets を置かなければ試運転モード（`data/records.csv` に記録）で動きます。管理者ページを試すときは、`.streamlit/secrets.toml` に次の2行だけ書きます。
```toml
[admin]
password = "test"
```
